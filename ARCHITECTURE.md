# Architecture

Target design for the first-principles reconstruction of Huntsman as the single package `huntsman-recon`. Every statement about the code is labelled. **CURRENT** means it is true of the repository tree containing this document and can be checked in `src/`, `tests/` or CI. **PLANNED** means it is a target that no code on `main` implements yet. The CAPABILITIES status column is CURRENT, MIGRATION POLICY is a rule set for every reconstruction PR, and ORDERED BACKLOG is PLANNED. `tests/architecture_doc.rs` checks the module map against the module tree `src/lib.rs` compiles (layer placement, the "Not compiled" row, upward edges and cycles), the section order, and the CAPABILITIES rows (pinned numbers and names, statuses, acceptance criteria and counts).

Engineering ownership and command routing are defined by [`docs/ENGINEERING_COMMAND.md`](docs/ENGINEERING_COMMAND.md) and the executable contract in `src/engineering_command.rs`; `huntsman-recon command` validates and prints that contract. Names there are repository-internal engineering codenames and do not alter collection or evidence semantics.

The capability oracle is git commit `7dca720` (root crate `huntsman-search-engine` v1.41.0, binary `hse`, published as pre-release `main-7dca720`, the newest `hse` build and the default of `.github/scripts/install-termux.sh`). historical Git tree `58adb561ddad030092838234c69ed63e2c1a0314` is a different, earlier snapshot of the same monolith (its `src/` differs from `7dca720` in 677 paths: 56 present in only one tree, 621 with different bytes). It is used for per-file accounting in `docs/ARCHIVE_PROVENANCE.md`, and as the oracle only where `7dca720` lacks a path (`src/modules/au_people/` and `src/modules/au_electoral/`, both deleted in #635). The extracted trees are absent from the active repository; the oracle is taken from a Git worktree of that historical tree.

## OBJECTIVE

CURRENT: `huntsman-recon` is an offline-tested core with a guarded fetch layer, a skip-tested `people` CLI over keyless ASIC registers, an `email` CLI with deterministic email derivation plus public Gravatar enrichment, a `username` CLI with deterministic handle variants plus keyless GitHub/Bluesky enrichment, an offline `phone` CLI with E.164/country/AU numbering-plan enrichment, a `scan` selector router over the rebuilt people/email/username/phone front-ends, bounded offline `investigate`, a minimal embedded `serve` UI/API, an opt-in `hibp` CLI, an opt-in `seeknow` CLI, and a `recon` CLI for crt.sh, DNS/mail (DoH), and stolen.tax. It is **not** a complete people-centric OSINT tool yet. Recursive scan remains absent and batch scan is bounded/partial:
- `resolve` exits 64 (`unknown command`); `scan` handles one selector or `--input-file FILE`, and `scan --recurse` adds a bounded multi-kind entity-expansion crawl over the shared limits (the offline engine is unit-tested; a full legacy depth differential and live receipts remain open). `investigate` and `serve` are present as partial rebuilt front-ends.
- `search` without `DIR` searches a built-in 2-document fixture.
- `hibp` is the only caller of `src/hibp/` outside tests. `username` is the caller of `github_user`, `bluesky_user`, `keybase`, `atproto`, `username_variants` and `username_save`. `seeknow` is the caller of `seeknow` / `seeknow_collector` / `seeknow_cli`. `recon crtsh` / `recon dns` / `recon stolen-tax` are the callers of `crtsh`, `dns` (plus `spf`/`dmarc`/`tlsrpt` parsers) and `stolen_tax`. `service_defs` is also used by the `credential-status --probe` provider-health path. `ckan` is called by `asic_persons`; `people_cli` is the `people NAME [--save FILE]` front-end over `asic_persons`, `asic_director`, `au_people` and `au_electoral` (skip path tested; one source Invalid does not abort the others; `--save` writes an unverified ledger `verify` reloads; live sources not run in CI) and feeds evidence through `lineage::resolve_with_lineage`.
- Identity-resolution logic is exercised by `check` fixtures and by the `people` lineage-rendering path; there is still no standalone `resolve` command or unified recursive resolution pass.
- Commit `f0a1c64c` removed all legacy providers (195 provider directories and 10 top-level files under `src/modules/` at `7dca720`) and the `scan`, `investigate` and `serve` commands.

PLANNED: a Termux-native CLI where a person selector goes in, keyless and operator-keyed sources are collected through one guarded network path, responses become evidence whose lineage comes from the response data, identities are resolved by a non-compensatory merge rule, and the result is saved, verifiable with `verify`, and printed with stable exit codes. Every capability of `hse` at `7dca720` is restored with a differential test against it; none is removed or dropped silently.

## CAPABILITIES

Every row's acceptance criteria include **D** and **N**:
- **D**: a differential test against legacy `hse` 7dca720 output on the same recorded inputs (see VERIFICATION).
- **N**: no dropped, truncated or misattributed results relative to that output.
- **L**: one live run against the real source, with a receipt (command, UTC time, response hash, exit code) tied to the commit SHA.
- **S**: SECURITY LEAD review, required for every boundary and credential-handling change.

## ARCHITECTURE

CURRENT. One package and library (`src/lib.rs`). `src/main.rs` is a thin composition root; command dispatch lives in `src/cli/mod.rs`, command adapters are grouped under `src/cli/` (no CLI framework), and `huntsman-recon` is the only executable. The table is the module map: every module `src/lib.rs` declares appears in exactly one layer row. A module may use modules in its own layer or a lower one, never a higher one. Dependencies are the `crate::` paths (`use`, `pub use`, groups and inline paths, plus `super::` paths that reach the crate root) in compiled code outside `#[cfg(test)]`; `tests/architecture_doc.rs` recomputes them and fails if either line below is wrong:
- Upward edges: none.
- Dependency cycles: none.

Binary adapter structure:
- `src/main.rs` owns process startup only.
- `src/cli/mod.rs` owns top-level argument dispatch; `src/cli/report.rs` owns the stderr reporter `fail`, which writes the control characters of a message escaped. Process exit statuses are defined once, in `src/exit.rs`, a library module with no dependencies (L0).
- `src/cli/{network,service,utility,meta,scans}.rs` group process-facing commands by responsibility (`scans` drives saved scans through the same `scan_api` router as `serve`); `lookup.rs` is a facade over `lookup/{profiles,scan,discovery,plan}.rs`; `help.rs` owns per-command help and `selfcheck.rs` owns offline acceptance.
- `src/cli/mod.rs` imports no library modules. Each adapter declares its own library dependencies explicitly; parent wildcard imports are forbidden so coupling remains visible and reviewable.
- Domain behavior and reusable logic remain in the library crate. CLI modules may orchestrate library calls but must not become a second domain layer.

## BOUNDARIES

CURRENT:
- Credential slots: `src/environment.rs` names every credential slot (`*_ENV`) and the `serve` bearer token, and it is the only production module that writes one of those names as a string literal. Other modules refer to the constant. `tests/architecture_boundaries.rs` enforces this, so a provider's slot cannot drift between the keys file, the service registry, the credential manifest and its client.
- Process boundary: `src/environment.rs` is the only library module that reads the process environment, through one named accessor per setting. The binary's adapters (`src/cli`, `src/bin`, `src/main.rs`) alone read the environment or the process arguments, write to the terminal, or end the process. Library code takes those as values. `tests/architecture_boundaries.rs` checks these rules on the token stream of production code, and checks its scanner on a sample of every forbidden name, so a rule cannot pass by finding nothing.
- Outbound HTTP socket creation remains centralized in `http::UreqTransport` (blocking `ureq` 3, rustls). Its `resolve` is the one system-resolver path (the C library's `getaddrinfo`, bounded by `RESOLVE_TIMEOUT`), which the DNS blocklists use because Spamhaus and SURBL refuse public DoH resolvers; other transports fail it. Its `exchange_udp` is the one UDP path: one DNS message to one server from a fresh socket connected to it, refused before sending when the egress policy refuses the server, which the filtering resolvers that offer no DoH over HTTP/1.1 (Comodo, Quad9, DNS for Family, Yandex) use. The one deliberate inbound exception is `web_server::Server`, which owns the `TcpListener` for `serve`. Its client half, `serve_probe::probe`, opens loopback connections to a running `serve` for `doctor`; no collector/source module opens sockets directly.
- `UreqTransport` resolves through `GuardedResolver`, which drops every address `egress::EgressPolicy` refuses. The default is `PublicOnly`, applied to the resolved addresses that are connected to, which defeats DNS rebinding. A refusal maps to exit 77.
- The transport never follows redirects (`max_redirects(0)`). `fetch::fetch` follows them; it attaches its `credential` argument only on the origin of the first URL (`src/fetch.rs:141-145`), and on a cross-origin hop it drops every header that `http::is_sensitive_header` names (`src/fetch.rs:272-275`).
- A `fetch::Credential` is built only from a `credential_origin::AuthenticationAuthority` (`src/fetch.rs:48`), and nothing converts a `DiscoveredCredential` into one, so a secret found in collected data cannot become a `fetch` credential. Two library paths put a secret into a request themselves and call `fetch` with `credential: None`:
  - `hibp`: the explicit `hibp` CLI now reaches this path. `src/hibp/client.rs` sets the `hibp-api-key` header from `ApiKey::expose()`, and `hibp::oauth::exchange_code` and `refresh` put the authorization code or refresh token in a form body. Origin protection is `hibp::trusted_url` (`https`, port 443, no userinfo or fragment, trusted HIBP/Pwned Passwords hosts) plus exact HIBP-origin checks; `hibp::send` disables redirects (`max_redirects: 0`).
  - `service_defs::probe_service` places its `key: &str` argument as the service's `KeyPlacement` says and sends it to the service's fixed `test_url`; `credential-status --probe` calls it only for configured single-slot providers with a registered probe. HIBP uses `/subscription/status` and the canonical Huntsman HIBP `User-Agent`. A key in a header is dropped on a cross-origin hop, because every header placement name in the registry contains `key` or is `Authorization`.
- Bodies are read under a byte cap and flagged `truncated`. Sensitive headers never appear in `Debug` output, and diagnostics pass through `redact::scrub_secrets`.
- `keys` refuses a keys file that group or others can access (`mode & 0o077 != 0`; 600 or stricter passes) and prints slot names and fingerprint prefixes, never values. `keys::store_slots` (and `store_slot`, its one-change form) is the one writer of the keys file: under one process-wide lock it applies every change in one rewrite, replacing the line that sets each slot (dropping any later line that sets it again), or removes it, keeps every other line byte for byte, checks that the result reads back to exactly those changes, so one change it cannot save saves none, and writes it whole through `write_atomic_private` (mode 600, fsync, rename). It refuses a symlink, a non-regular file or another owner's file, and saves a too-open one back at 600; `serve`'s `POST /api/settings/keys` (the Settings page's Set key, Remove and Import API keys, which `key_import` reads) is its caller. `provider_credentials` composes this loader with `service_defs` for status/probe output without carrying credential values into its result types.
- Without `--keys`, a `fetch` that requests a credential reads `$HOME/.huntsman.env` through `Keys::resolve` (called from the CLI adapter layer in `src/cli/`), only for an absolute `HOME`. The file is not read, with one stderr warning, if `lstat` shows a symlink, a non-regular file, an owner other than the effective uid (or the uid cannot be read), or `mode & 0o077 != 0`. It is read through the opened descriptor, which must have the device/inode `lstat` saw and pass the same checks. A file that passes but is malformed, not UTF-8, over 64 KiB or fails with an I/O error other than not found makes the `fetch` exit 66 (`tests/env_autoload.rs`).
- Library code that sends takes its transport as an argument: `fetch::fetch` (`T: Transport + ?Sized`), `dns::resolve_with_pool` and `resolve_with_config` (DoH through `fetch`, no redirects), `postcode_au::localities_with` (`T: Transport`), `service_defs::probe_service` (`T: Transport + ?Sized`), `asic_persons::lookup` (`T: Transport + ?Sized`), `asic_director::lookup` (`T: Transport + ?Sized`), `au_people::lookup` (`T: Transport + ?Sized`), `au_electoral::lookup` (`T: Transport + ?Sized`), `people_cli::run` (`T: Transport + ?Sized`), `seeknow::search_fast` and `seeknow::search_deep` (`T: Transport + ?Sized`), `seeknow_cli::run` (`T: Transport + ?Sized`), `web_query::search` (`T: Transport + ?Sized`), `gravatar::lookup`, `github_user::lookup`, `bluesky_user::lookup`, `keybase::lookup`, `blockchain::lookup`, `username_cli::run` and `crypto_cli::run` (`T: Transport + ?Sized`), the `hibp::oauth` functions (`&dyn Transport`) and `hibp::HibpClient::new` and `with_config` (`Arc<dyn Transport + Send + Sync>`). The one exception is `HibpClient::production` (`src/hibp/client.rs:154-161`), which builds its own `UreqTransport` with the default egress policy. Tests inject fakes; process-facing commands construct `UreqTransport` only in the binary adapter layer under `src/cli/`, while `hibp` calls `HibpCommand::production()`.

PLANNED: every new source goes through `fetch` and the guarded transport; no module adds a second HTTP client. Gap to close: `hibp` and `service_defs::probe_service` send keys through a `fetch::Credential` built from an `AuthenticationAuthority` instead of setting them themselves, and `HibpClient::production` takes its transport from the caller. Every change to `egress`, `http`, `fetch`, `keys`, `credential_origin`, `hibp` key handling requires Security & Secrets Bot review.

## CONTRACTS

CURRENT:
- `http::Transport::send(&Request) -> Result<Response, TransportFailure>`. A non-2xx status is a `Response`, not an error.
- `fetch` returns a typed `source_outcome::SourceOutcomeKind` and never "found": a 200 is `Inconclusive` until a parser produces rows, and a challenge page is `BotWaf` at any status.
- `source_outcome::recommended_action` maps an outcome to `Accept`, `Retry`, `Backoff`, `RequireCredential`, `Quarantine`, `RequireContractVerification` or `Investigate`.
- `identity_resolution::IdentityResolutionDecision::allows_automatic_merge` is `hold_reasons(..).is_empty()` and non-compensatory: one contradiction, a temporal or geographic conflict, unknown ancestry, or a missing, non-finite, out-of-range or below-floor probability blocks the merge regardless of support. Each failed condition is returned as a `HoldReason`, in a fixed order (`docs/LINEAGE.md`).
- `lineage::resolve_with_lineage` returns every observation and every candidate in input order, each candidate `AutoMerge` or `Held { reasons }`; it drops nothing.
- `ledger`: each entry's hash covers the previous hash plus the claim. `verify` prints `entries`, `admitted` and `tip`, and exits 65 on a broken chain.
- CLI exit codes: 0 success, 64 usage, 65 bad data or invalid request, 66 unreadable input or missing required credential, 69 unavailable/no response, 74 artifact write failure, 77 egress/auth/entitlement refusal; `check` uses 2–11 for its gates. `hibp` reuses 64, 65, 66, 69 and 77 and adds no new process exit code. `tests/readme.rs` enforces the shared code set against `src/exit.rs`, the only place these numbers are defined.

PLANNED:
- Collector contract: `collect(selector, &dyn Transport) -> (SourceOutcomeKind, Vec<Evidence>)`. Zero rows with a `Success` outcome is `ValidZero`, not a failure.
- Each people-lookup command documents and tests the same exit-code set.

## INVARIANTS

CURRENT:
- `unsafe_code` is forbidden and clippy `pedantic` is warn, both set in `[lints]` in `Cargo.toml`; CI denies warnings.
- A challenge page is never a result. A self-labelled ATT&CK technique never enters Navigator or STIX (`check` gates).
- `check` regenerates `var/*.json` byte-identically. Every `gate` mode runs `check` and refuses the run if it changes any tracked or untracked content, or if a commit moves HEAD during the run (`xtask/src/gate.rs`, `baseline` and `drift`).
- Every gate mode first validates the changelog fragments under `changelog.d/` (`xtask/src/changelog.rs`, `check`): a fragment is `<slug>.<section>.md` holding Markdown bullets, assembled into `CHANGELOG.md` by `changelog assemble` when a version heading is cut, so pull requests never edit the same changelog lines.
- A gate run holds `target/repair-gate/gate.lock` for its checkout. A second run in that checkout is refused while the first holds the lock. A lock left by an exited process is taken over (`xtask/src/proc.rs`, `GateLock`).
- `tests/repository_hygiene.rs` forbids opaque archive snapshots at the repository root from returning; the historical archives' SHA-256/Git identities and a recoverable commit are recorded in `docs/ARCHIVE_PROVENANCE.md` and Git history.
- The README examples, usage line, exit codes and gate range match the binary (`tests/readme.rs`); this file's module map, dependency claims and capability rows match `src/` (`tests/architecture_doc.rs`).
- Every `.rs` file under `src/` is compiled (#675); `tests/architecture_doc.rs` fails on a file the module tree does not reach.
- In `lineage`, mirrors of one named dataset count as one family whatever the collectors are called, and record URLs, record ids and collector names never create a family (`tests/lineage_merge_rule.rs`, `tests/lineage_independence_adversarial.rs`).
- Automatic merge requires a present, finite probability in `[0, 1]` at or above the policy floor; `probability: None` holds the candidate (`HoldReason::ProbabilityMissing`).
- Entity corroboration recomputes the source key from current provenance rather than trusting a serialized `source_family`; tampering with the stored family cannot manufacture corroboration (`tests/corroboration_key.rs`, #685).

PLANNED:
- Every collector's output goes through `lineage`, so mirrors of one dataset count as one source end to end.
- Collectors supply a calibrated match probability; `lineage` supplies none.
- No result reaches output without a lineage root.

## DATA

CURRENT:
- `entity::Entity` carries `entity::Evidence`; each `Evidence` has an `EvidenceProvenance` (`source`, `source_family`, `scan_id`, `recorded_at_unix`) and an optional `ancestry_node`.
- `evidence_ancestry::EvidenceAncestryNode` has `id`, `source_family`, `parents` and `derived`. `canonical_family` only normalises case and whitespace. Callers set these fields, except `lineage::resolve_with_lineage`, which builds the graph from `Evidence::attributes`.
- Lineage (#679, `docs/LINEAGE.md`): `lineage::Lineage::of` takes the family from the first non-blank response field among `dbname`, `breach`, `source_db`, `database_name` and `dataset`, or `registry` only from a collector in `VERIFIED_REGISTRY_SOURCES` (currently `abn_lookup`), matched on the family recomputed from an ASCII `provenance.source`, never the stored `source_family` (#684); never from the collector name, `source_url` or `source_id`. Each family is one root `lineage:<family>`, so two collectors relaying one dataset share one root. A response that names no dataset, or several in one field, is kept and contributes zero families.
- Files: `check` writes `var/ledger.json`, `var/navigator.json` and `var/stix-bundle.json`. `store` writes bounded (the saved-artifact ceiling, 32 MiB) JSON sessions atomically and refuses symlinks. `hibp::oauth` token files are mode 600.

PLANNED, lineage: collectors fill those fields from the response data: the dataset or breach identifier the response reports (for example the HIBP breach `Name`, a CKAN `resource_id`, a crt.sh log entry), plus any upstream the response itself names. A response that names no dataset gets a root derived from the source origin and the response hash, marked `derived: false`, which cannot by itself justify an automatic merge (today it contributes zero families). Dataset names are not yet canonicalised for Unicode confusables or zero-width characters (`docs/LINEAGE.md`, trust boundary).

## FAILURE MODEL

CURRENT:
- Network failures are typed outcomes (`DnsFailure`, `ConnectFailure`, `TlsFailure`, `TtfbTimeout`, `BodyTimeout`, `RateLimited`, `AuthRequired`, `NotConfigured`, `AuthRejected`, `BotWaf`, `Upstream4xx`, `Upstream5xx`, the drift kinds and others), not panics or empty results.
- Library errors (`error::Error`) have no fail-open path. Ancestry with a missing node or a cycle fails closed: unknown ancestry is not independence.
- `hibp` bounds 429 retries, treats truncated or malformed bodies as errors, and fails closed on missing entitlement flags. Public catalogue/account/paste 404 semantics are explicit in the CLI tests; Pwned Passwords 429 is not retried.
- A failure is never reported as `hits=0`: an unreadable `search` directory exits 66.

## MIGRATION POLICY

Rules for every reconstruction PR from this one on:

- One capability per PR, with its tests, its README example (enforced by `tests/readme.rs`) and its CAPABILITIES row update.
- Port behaviour, not structure: legacy is the oracle, not a source to copy wholesale. Async code is rewritten as blocking code over `http::Transport`.

### Reproducible graph scheduling comparison

Run `cargo test --locked --test graph_exec measured_sequential_vs_bounded_graph_synthetic_io -- --nocapture`
from the repository root to print a JSON timing record. The ordinary test suite
also executes the benchmark but captures its output unless run with `--nocapture`.
The benchmark executes four
independent synthetic, fixed-latency blocking lookups first in sequence and then
through the graph executor at concurrency two. It checks equivalent outputs,
success counts and termination status; no speedup threshold is asserted because
CI scheduling can vary. Both durations are measured in milliseconds, not
estimated. This measurement does **not** establish live-API performance, paid
API costs, false-positive rates or performance on an Android handset. Those
require an additional controlled provider/device workload with a captured
baseline before any concurrency increase.
