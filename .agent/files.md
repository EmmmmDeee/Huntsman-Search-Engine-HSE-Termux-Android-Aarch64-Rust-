# Repair queue

Every tracked file, highest repair priority first. The list is a snapshot of
the tree when the 2026-09-23 run began. Work goes top-down, and
`.agent/progress.md` records the cursor (the next file) and what each file's
pass found. A full pass on a file reads all of it. Each real defect found
becomes one change under the maintainer procedure: a failing check first,
the smallest complete fix, a revert check, and a fresh-worktree
verification. A file with nothing to fix is recorded as such, with what was
checked.

**Score** = reach × (1 + ln(1 + fan-in)) × (1 + ln(1 + defects)) × ln(2 + lines)

- **reach**: how directly an operator runs the file.
  - 1.0: prod-rust.
  - 0.9: web-ui.
  - 0.8: lifecycle (install.sh, Dockerfile, docker-entrypoint.sh,
    scripts/reconcile.sh, Cargo.toml files).
  - 0.7: wasm-ui.
  - 0.5: tool (src/bin) and ci/tooling.
  - 0.4: other Rust.
  - 0.35: test.
  - 0.3: bench/fuzz.
  - 0.15: docs.
  - 0.05: data, lockfile and state.
- **fan-in**: other files that name the file's module through a `use` path
  or an inline `crate::` path. Each path is credited to the deepest module
  that owns it, so `use crate::core::{engine::X}` counts for `core::engine`,
  not `core`. For web JS, it counts imports of the file name.
- **defects**: commits whose subject reads as a fix and that touched the
  file, over the full history of 3010 commits. Plus the
  `## REQ-` entries in `docs/REQUIREMENTS_LEDGER.md` that name the file or
  its module.
- **lines**: line count, 0 for a binary file.
