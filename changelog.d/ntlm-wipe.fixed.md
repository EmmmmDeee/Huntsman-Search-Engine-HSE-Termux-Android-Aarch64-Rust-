- Checking a password in NTLM mode (`HibpClient::check_password` with `PasswordHashMode::Ntlm`; the `hibp password` command uses SHA-1) now overwrites the password's copies with zeros after use, as the SHA-1 path already did. The UTF-16LE copy of the password and MD4's padded message were left in memory, and the padded message grew while it was built, so freed allocations also held the password. Both buffers are now sized once, never reallocate and are wiped, and so are MD4's block words. As before, this is best effort without `unsafe`, and stdin's read buffer is not reached. `hibp::tests::ntlm_password_buffers_never_reallocate_so_the_wipe_reaches_every_copy` fails on the old buffers.
