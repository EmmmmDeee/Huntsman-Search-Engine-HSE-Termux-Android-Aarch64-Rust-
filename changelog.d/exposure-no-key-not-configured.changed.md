- A keyed source with no key configured now reports `not_configured` instead of `auth_required`. It makes no request in either case, but a missing key is an expected state the operator can fix, not a failed credential. A scan logs these legs as information rather than errors and does not count them toward its error total, so an email or username scan on a device with no keys no longer shows the keyed breach and lookup skips as failures. The outcome is kept whole: the same detail line, including the HIBP free-check hint, is still recorded, and a configured key still runs. `auth_required` keeps its meaning of a real HTTP 401 without a credential.
