When `merge_by_uid` folded two records with one summary (the same address looked up on two days and loaded together, or met twice in one crawl), `merge_evidence` split every differing attribute on `; `, sorted the pieces and joined them again. A source's answer kept whole as JSON (`raw_answer`, `raw_pulses`) can hold `; ` inside its text, so the merged value was no longer JSON. Pieces from the two answers were spliced into records neither source gave: two OTX pulse lists merged into a pulse named `Scanner; actively exploited`. A JSON document is now kept whole, and the later record's document replaces it whole. Listed values still keep every value from both records.
