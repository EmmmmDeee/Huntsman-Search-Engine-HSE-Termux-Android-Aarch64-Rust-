- A key stored in `~/.huntsman.env` under a name that matches no provider slot — a misnamed key, for example `HUNTSMAN_SHODAN` instead of `HUNTSMAN_SHODAN_KEY`, or a dropped `_KEY` suffix — is now reported instead of silently ignored. Before this, the keys file parser accepted any environment-variable-shaped name, `doctor` counted it in "N slots set", but nothing read it and nothing said so: `credential-status` and `doctor` only ever iterated the known providers, so the keyed source the slot was meant to configure silently never ran and the operator had no signal that their key was in the wrong place. `credential-status` now lists each such slot as `unrecognised_slot=<NAME>` with guidance to rename or remove it, and `doctor`'s `env_file` check warns and names the unrecognised slots. Both report names only, never values. `environment::KNOWN_VARIABLES` is the single registry of every variable `huntsman-recon` reads (all credential slots and runtime settings), and a regression test ties every provider slot and the per-provider cost variables to it so a newly added provider key can never be falsely flagged.
