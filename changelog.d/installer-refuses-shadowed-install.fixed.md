- The Termux installer now refuses to report success when a different `huntsman-recon` (or `huntsman`) earlier on `PATH` shadows the binary it just installed under `$PREFIX/bin`. Before this, a stale copy left from an older layout — commonly `~/bin/huntsman-recon` — silently won whenever the command name was typed, so every reinstall printed "installed and accepted" while the old binary kept running, and an older build does not recognise the current key slots (which looked like configured keys going unread). The installer now resolves each command name, compares it to what it installed, and stops with the shadowing path and how to remove it when they differ. A root-installer regression test reproduces the shadow and locks the refusal.
