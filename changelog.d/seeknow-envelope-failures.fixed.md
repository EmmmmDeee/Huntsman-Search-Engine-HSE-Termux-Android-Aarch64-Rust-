- `seeknow search`, `seeknow status` and `seeknow credits` treat an HTTP 200 answer whose envelope says `"success": false` as a failed request. `seeknow search email alice@example.com` answered with `{"success":false,"error":"search backend unavailable","data":[]}` printed `outcome=valid_zero` and exited 0, and without `--fast-only` it then spent a 2-credit `/stealer` request on that zero; rows sent with `"success": false` were reported as a success. It now exits 69 with `SeekNow collection outcome=inconclusive` and sends no `/stealer` request. `seeknow status` and `seeknow credits` answered that way printed `outcome=success` and exited 0; they now exit 69 with `SeekNow outcome=inconclusive detail=provider reported request failure`. In email, username and people lookups, scans and saved ledgers the `seeknow_search` outcome is `inconclusive` (HTTP 200, found 0) instead of `valid_zero` or `success`. A rejected key or a missing plan keeps its own outcome, and a 200 that carries an `error` but no `"success": false` is unchanged.
- A SeekNow 429 whose body is the JSON envelope keeps the provider's pause. With `Retry-After: 30` and `{"success":false,"error":"rate_limited"}`, the outcome recorded `retry_after_secs: null`, so scan status JSON, the scan log's `retry_after_s=` and the web UI's "retry after N s" showed no pause, while the same 429 with a non-JSON body kept it. The outcome now carries the `Retry-After` value (at most 3600 s), whether the envelope reads as a rate limit, spent quota, rejected key or missing plan.
- A SeekNow row whose `dbname`, `breach`, `source_db`, `database_name`, `dataset` or `source` is an array of more than 64 values, or holds an element over 4096 characters, is marked truncated. Only the first 64 values were kept and over-long elements were dropped, but the row's `fields_truncated` stayed false, so its entities lacked the `normalization_truncated=true` evidence attribute in lookup ledgers and scan elements. They now carry it; the same 64 values are kept, and `seeknow` CLI text is unchanged.
