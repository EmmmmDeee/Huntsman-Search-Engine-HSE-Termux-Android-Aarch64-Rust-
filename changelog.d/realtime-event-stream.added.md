- The Web UI now updates in real time instead of polling every five seconds. `serve` streams Server-Sent Events on `/api/events`: the scan service publishes every committed scan-status change and a continuous cycle publishes each raised alert to a bounded in-process hub, and the page's `EventSource` refreshes the open view the instant one arrives. The stream applies the same loopback and token guards as the rest of the API, each connection streams for at most 25 seconds before the browser reconnects (bounding how long it holds one of the server's connection slots), and the events carry only a scan id, status and each alert reason's risk and rule — never a target. `curl -N http://127.0.0.1:PORT/api/events` streams the same events for scripting.
