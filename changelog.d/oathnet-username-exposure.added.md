- A configured paid breach source is never skipped. `email ADDR`, `username HANDLE`, `scan` of an address or handle (with or without `-k`, so batch scans too) and the web UI's `auto`, `email` and `username` lookups now also run every exposure leg whose key is set: HIBP for an address, and stolen.tax and OathNet for either. Before, those legs ran only for `exposure` or `-k exposure`, so an ordinary scan of an address left a configured key unused. The report is one entity and outcome table, followed by the incidents and OathNet sections, and a saved ledger names each leg's own module. With no breach key set, no breach request is made and the report is unchanged. An exposure run that gives no report adds one `exposure=unavailable reason=...` line, and the lookup still succeeds. Each looked-up address or handle spends one OathNet and one stolen.tax lookup.
- `exposure` also takes a username: `exposure @handle`, `scan -k exposure HANDLE` and the web UI's exposure lookup search stolen.tax and OathNet for it (HIBP searches addresses only and is skipped without a request). OathNet's records for a username give its breach databases and the addresses found with it, which become pivots. An address is never read as a handle. One OathNet lookup now reads 200 records, the most one request returns, instead of 100, at the same quota cost.
