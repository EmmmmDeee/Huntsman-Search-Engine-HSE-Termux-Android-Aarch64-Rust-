- `apk FILE` now reads each native library's **`SONAME`** (the canonical name the library records for itself) and its **`DT_NEEDED`** list (the shared libraries it links against) from the ELF dynamic section, alongside the GNU build-id — all offline and without loading or executing the library. Stripped C/C++ native code carries no Java package names, so the DEX SDK fingerprint cannot see it; the linked-library list is a native dependency fingerprint that can, for example, reveal the native engine an app is built on. The dynamic string table is referenced by virtual address, so that address is translated to a file offset through the `PT_LOAD` segment that maps it; every offset is bounds-checked and an entry whose name runs past the string table is dropped, never misread. Reported per library as `analysis.native_build_ids[].soname` / `.needed` in the JSON and summarised on the document evidence as `apk_native_dependencies`, and each library's build-id pivot entity now carries its `soname` and `needed_libraries` as attributes. A library that declares a `SONAME` or `NEEDED` list but carries no build-id is now recorded too (it just has no build-id pivot). At most 64 needed libraries are kept per library; no new dependency.
