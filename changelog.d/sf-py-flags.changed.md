- `sf` takes the rest of `sf.py`'s flags. `-F TYPE[,TYPE...]` prints only those types without changing what the scan keeps, where it used to be an alias of `-t`; `-f` and `-x` print only the `-t` types, and without them `-t` now prints every element the scan kept, the target included, as `sf.py` prints every event of the modules `-t` picks. `-H` leaves out the header, `-n` turns line breaks in data into spaces, `-S LENGTH` cuts each value to that many characters, `-D DELIMITER` sets the CSV delimiter, `-d` prints the scan's log to stderr, `-l IP:PORT` serves the web UI as `serve --bind` does, and `--depth N` follows what the scan finds as `scans run --depth` does. `-f` or `-x` without `-t`, `-x` with `--depth`, and `-D` outside CSV are refused, as `sf.py` refuses them.
- `sf` rows now match `sf.py`'s. Tab rows pad the module to 30 characters and the type to 45. A JSON row has `sf.py`'s keys, `generated`, `type` (the type's description), `data`, `module` and `source` (the source element's data), plus `event_type`, `id`, `source_id`, `confidence`, `false_positive`, `entity` and the raw evidence; `source` used to hold the module and `source_data` the source data, so a script reading those keys must follow.
