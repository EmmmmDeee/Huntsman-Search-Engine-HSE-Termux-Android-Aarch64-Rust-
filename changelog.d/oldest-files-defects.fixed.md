- `scan --recurse --expand-floor F` now reaches the gap report. Orphans were always judged against the default 0.5, so with `--expand-floor 0.1` a 0.3 domain the crawl did expand was reported "below the expansion floor", and with `0.9` a 0.7 domain it refused was reported "unexpanded". The text `orphan` lines and the JSON `gaps` now use the floor the crawl used. Default runs are unchanged. The report also reuses the analysis graph instead of building it a second time.
- `plan`, `scan --recurse` and a saved session's falsify record now name the stop reason as JSON, `scans analyze` and the web UI do: `termination=fixed_point`, not `termination=FixedPoint`.
- `fetch --header NAME=SLOT` refuses a name that is not a token (empty, or with a space or colon) as a usage error (exit 64), before reading the keys file. It used to exit 66 with `credential SLOT is not configured` or a token message, and without the usage text. `fetch --keys` refuses a missing or flag-shaped path (`--keys needs a file path`) instead of taking the next option as the file.
- A Bluesky profile's DID becomes an entity only when it is a `did:plc:` identifier (24 base32 characters) or a `did:web:` domain. A malformed or hostile value, such as a path, stays on the profile's evidence as `did` and is no longer a pivot.
- A `bsky.app` profile URL now names the same handle as the Bluesky username lookup. It strips every platform suffix the lookup strips (`.bsky.social`, `.bsky.team`, `.brid.gy`, `.translate.goog`), in any case. So a username and its own profile URL link for those handles too.
- The STIX export leaves out a ledger entry whose hash is not at least 32 hex digits. Such an entry used to panic the export on a non-ASCII hash, or share a zero-padded id with another short hash. Every sealed entry has a 64-digit hash and is unaffected.
