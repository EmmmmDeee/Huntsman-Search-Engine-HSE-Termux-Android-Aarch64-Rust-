- `apk FILE` now resolves an app's **displayed name** — the single most human-recognisable fact about an app. `android:label` is almost always a resource reference (`@0x7f…`) rather than a literal, so the name cannot be read from the manifest alone; `apk_intel::arsc` now decodes the compiled resource table (`resources.arsc`) and resolves that reference to its string. Only what resolving the one id requires is read — the table's global value string pool and, in the matching package, the type chunks for the requested type until an entry yields a string — with every offset and length bounds-checked, so a malformed or truncated table yields nothing rather than a misread. A literal label is taken inline. Reported as `analysis.app_label` in the JSON and `apk_app_label` on the document evidence. The name is the manifest's own claim, never verified against a store listing, and resolution that fails or is ambiguous leaves it unknown rather than guessed (the base/default-configuration string is returned, never a wrong one). No new dependency — the deflate for `resources.arsc` is the one already built into the binary.
