- A refusal the web UI server writes while the browser is still sending a file, such as the `503` for an inspection already running, the `413` for a file over 64 MiB or the `408` for an upload that stalled, now reaches the browser as that status. The server used to close the connection with the rest of the body unread, so the kernel answered the browser's next segment with a reset, and a browser that does not re-read an answer after a reset (Firefox for Android, for one) showed a network error that blamed a stopped server. The server now half-closes after answering and drains what the request announced, within the budget an admitted upload would have had.
