- An `email` lookup now reports a Duolingo account whose public profile the site withholds. Duolingo changed its `users?email=` endpoint to return a user stub with blank `username`, `name` and `id` for a registered address (observed 2026-11-04), reserving an empty list for an address with no account. Huntsman was treating the blank stub as schema drift and discarding it, so a confirmed account read as a parse failure. The stub's presence is now a confirmed account-existence match: the queried address is kept as an `account-exists` lead with its profile marked withheld, and no handle, name or location is invented from the blank fields. A genuinely malformed response (missing or wrong-typed `users` field, non-JSON) is still drift.
