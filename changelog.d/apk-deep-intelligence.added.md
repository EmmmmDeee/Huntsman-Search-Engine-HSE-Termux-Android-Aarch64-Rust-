- `huntsman-recon apk FILE` and the serve APK-upload path now read an APK's contents, not just its ZIP inventory, all offline and keyless. The binary `AndroidManifest.xml` is decoded (package, version, min/target SDK, permissions, the activities, services, receivers and providers other apps can reach, deep-link schemes and hosts, and `autoVerify` App Links), resolving attributes by their framework resource ID so a manifest with blanked attribute names still reads as Android reads it. The v1 (`META-INF/*.RSA`/`.DSA`/`.EC` PKCS#7) and v2/v3 signing-block certificates are summarised and identified by the SHA-256 of their DER, the digest `apksigner --print-certs` prints, so two APKs sharing a signer pivot to each other. The URLs compiled into each DEX string table are listed with their hosts. The signers, deep-link hosts and code hosts/URLs become pivot entities that meet domain, IP and other APK scans in the graph. Members are inflated within a per-APK budget and checked against their ZIP CRC-32; an archive trick that makes other tools fail while Android still installs the app (an unknown compression method read as stored) is reported as an evasion indicator. No signature is verified, nothing is executed or fetched, and a certificate name or a URL in code is a lead, never proof of authorship. This reproduces in Rust what `apksigner`, `aapt` and `apkleaks`/MobSF report, with no new runtime dependency (the deflate and CRC-32 code is already built into the binary).
