- A scan whose process stopped while the web server stayed up (Android stopping a Termux session that ran `huntsman scans run`, or a worker killed mid-scan) no longer shows RUNNING for ever with Stop and Delete both refused until the next restart. The scans list and a scan's page now reconcile such a row on read, marking it ABORTED with a log line naming the process that ran it; Stop settles it the same way and succeeds, and Delete then removes it like any ended scan. A scan another live process is still running is left as it is.
