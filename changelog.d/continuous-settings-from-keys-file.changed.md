- `serve` reads `HUNTSMAN_CONTINUOUS_TARGETS` and `HUNTSMAN_CONTINUOUS_INTERVAL_MINUTES` the way it reads every key: from `~/.huntsman.env` first, then the environment, so continuous normalisation can be configured in the file the Termux service already reads, and `doctor` and `credential-status` recognise both names instead of calling them keys no provider reads. The Settings tab's Global Settings shows what `serve` collects and how often, or that continuous normalisation is off and how to turn it on (`/api/settings` gains the `continuous` global). A wrong setting ends `serve` before it binds, naming the setting, rather than after it has announced its address.
