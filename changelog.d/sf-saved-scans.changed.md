- `sf -s` runs every target `scans run` runs, as a saved scan, and `sf -C ID` correlates a saved scan again, as Spiderfoot's `sf.py` does. A domain or an IPv4 or IPv6 address now scans through the `domain` and `ip` lookups; before, `sf -s example.org` was refused as "not available yet". Every target goes through the same saved-scan service as `scans run` and `serve`, so an email scan now runs its keyed breach sources and SeekNow leg, which `sf -s` used to leave out, and `-u passive` runs every target as `scans run -u passive` does instead of refusing all but a phone number. The scan is saved in `~/.huntsman/scans` with its elements and correlations, so `scans` and the web UI read it, and stderr names its id unless `-q` is given. A scan whose every lookup refused exits with the status and message of the plain lookup, as before; a name that is not two alphabetic words, a private or documentation address, or a netblock or AS number exits 65 without a request.
