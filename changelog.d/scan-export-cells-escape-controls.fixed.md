- A saved scan's CSV and TSV exports no longer pass control characters and bidirectional controls through to the reader. `scans export` without `-o` writes the file to standard output, and a value from a remote source reached it unchanged, so a crafted record could put an escape sequence in the operator's terminal to clear the screen, rewrite earlier lines or hide text, or put a right-to-left override in it to reorder what was read. A CSV cell now writes each such character as its Rust escape, such as `\u{1b}`, `\u{9b}` or `\u{202e}`, and so does a TSV cell after its tab, newline and backslash escapes. A carriage return is escaped in a CSV cell as well, since a lone one moves the cursor back over the line. A line feed and a tab stay as they were in a quoted CSV cell. The scan compare and correlation exports use the same writers. Each value is still written whole; only the characters that drive a terminal or reorder text are changed, and ordinary values are byte-identical.
