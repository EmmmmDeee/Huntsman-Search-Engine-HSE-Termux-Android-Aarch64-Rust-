- `apk FILE` now names the cross-platform framework or game engine an app is built on — Flutter, Unity (including IL2CPP), React Native (including Hermes), Xamarin/Mono, Qt, Cocos2d-x, Godot, Unreal Engine, libGDX, Defold — from the native libraries it bundles or links against (`libflutter.so`, `libil2cpp.so`, `libreactnativejni.so`, …). These engine libraries have stable, well-documented names, so their presence names the framework: a triage and attribution signal that survives stripping and Java obfuscation, which the DEX/Java SDK fingerprint cannot give. Each bundled library's own name, its `SONAME` and its `DT_NEEDED` entries are all matched, so an app that merely links an engine is named as well as one that bundles it. Reported as `analysis.native_frameworks` in the JSON and `apk_native_frameworks` on the document evidence. A framework names the build of one app, never a cross-APK pivot between apps — many unrelated apps share an engine. The signature list is a curated, auditable set of distinctive library-name stems; no new dependency.
