- Lookups use a key set in `~/.huntsman.env`. `exposure`, `username`, `network`, `scan`, `sf`, `hibp`, `recon stolen-tax` without `--keys`, and the web UI's lookups read keys from the environment only, and HIBP also read `~/.config/hibp/api_key`. `credential-status` reads `~/.huntsman.env` too, so it could report a key as set that no lookup then used. Every lookup now reads the same places as `credential-status`: `~/.huntsman.env` when it passes the default-file checks, then the environment, with the file's value winning when a slot is in both, as with `--keys`. HIBP takes `HIBP_API_KEY`, then the `HUNTSMAN_HIBP_KEY` slot from those places, then `~/.config/hibp/api_key`. A default file that is skipped or cannot be parsed prints one warning, never a value, and the lookup goes on with the environment's keys. `tests/architecture_boundaries.rs` now fails if production code reads keys from the environment alone.
