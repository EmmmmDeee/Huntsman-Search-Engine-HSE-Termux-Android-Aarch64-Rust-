- `scripts/hse-baseline.sh` is a bounded, read-only baseline for the Termux (aarch64, no-root) upgrade pass: it clones the repository, cuts a local-only branch off `origin/main`, runs the same checks the acceptance gate runs (`cargo run -p xtask -- changelog check`, `cargo fmt --check`, `cargo check`, the `clippy::unwrap_used` passes over the library and both binaries, `cargo clippy -D warnings` across the workspace, the test suite, and the `cargo run -- check` self-check) all with `--locked`, and always leaves `$WORK/reports/<stamp>/SUMMARY.txt` — even when a run aborts early. Running the gate's full check set means a green baseline on the handset implies a green gate in CI, rather than only proving that some checks passed. It never pushes, merges, commits, installs the app, or deploys; `tests/hse_baseline.rs` locks that read-only contract and the gate-faithful check set so a later edit cannot quietly turn the diagnostic into a mutation or let it drift behind the gate. A per-`WORK` lock serialises runs and heals itself: a lock left behind by a hard-killed run (its recorded PID no longer alive) is reclaimed on the next run instead of wedging every run that follows. `SKIP_TESTS=1` runs the checks without the tests and `RUN_RELEASE=1` adds the release build; `REF`, `WORK`, `JOBS` and `REPO_URL` are overridable.
