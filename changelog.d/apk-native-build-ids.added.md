- `apk FILE` now reads the GNU build-id of each bundled native library (`lib/*/*.so`) straight from its ELF note, offline and without loading or executing it. The build-id is a hash the linker stamps into a binary (`--build-id`, on by default in the Android NDK) and is unique to one compiled build of the library, so two APKs whose native libraries share a build-id shipped the same build — a cross-APK pivot the Java-level SDK fingerprint cannot see (stripped C/C++ code carries no package names). Only the ELF header, program headers and the build-id note segment are read, every offset is bounds-checked, and a file that is not a little-endian ELF or whose headers do not fit is skipped. Reported as `apk_native_build_ids` on the document evidence and as `analysis.native_build_ids` (library, ABI, build-id) in the JSON, and each build-id becomes an `apk-native-buildid:<id>` pivot entity that meets other APK scans in the graph. At most 64 native libraries are read, each within the existing per-member byte budget; no new dependency and no decompression beyond the deflate already built into the binary.
