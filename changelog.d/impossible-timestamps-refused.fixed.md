- Impossible timestamps are refused instead of silently corrected. `rf::parse_iso8601_epoch` (the Wi-Fi sighting time) accepted any day from 1 to 31 in any month, so `2026-02-31` became 3 March, accepted signed fields such as `-1` for an hour, and read trailing text after a valid-looking offset as part of it. It now checks the day against the real month length, accepts only ASCII digits in each field, requires a well-formed fraction, and parses the offset with the same strict rule as `timefmt`. The X.509 `UTCTime` and `GeneralizedTime` reader (`x509::time`) checked only the length and the digits, so `251301000000Z` became `2025-13-01T00:00:00Z`. It now checks the month, day, hour, minute and second the same way. Both use `timefmt`'s calendar and offset rules rather than their own copies. Leap second 60 is still accepted, as before; whether to keep it is a separate decision.
