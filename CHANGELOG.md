## [Unreleased]

### Added

- A module can now say **"not attempted"** in-band: `Error::skipped(class, reason)` (`core::error::Error::Skipped`) is a typed skip the dispatcher records as a `ModuleSkipped` event carrying the module's `SkipClass` and reason, tallied under `modules_skipped` — never a `ModuleError` (which trips the circuit breaker and degrades module health for a decision, not a fault) and never an empty `ModuleDone` (which `core::coverage` aggregates to `CleanNegative`, the one outcome the design treats as a real negative). A `NotApplicable` skip vanishes from the coverage verdict; an `Unavailable` one is an actionable gap. Until now a module's only in-band options were a failure or a clean negative, so every structural "this provider cannot speak about this target" (a registry with no WHOIS server, port 43 unroutable behind a proxy) was misreported as one or the other. Locked at the engine boundary (`tests/smoke.rs`) and in the error Display drift guard.
- `scripts/reconcile.sh` — the HSE capability reconciler: a deterministic, fail-closed, evidence-gated controller that converges a checkout and a Termux device onto the state the live radar needs (OBSERVE → NORMALIZE → DECIDE → MINIMAL MUTATION → VERIFY → ROLLBACK ON FAILURE → RE-OBSERVE → VERDICT). Repository side: recognises the installer's `termux-info` sentinel defect by SOURCE CONTENT (the exact block) and the fix by its own signature, snapshots only `install.sh`, patches it, verifies with `bash -n`, structural invariants, `git diff --check`, `cargo fmt --check` and the targeted `install_invariants` tests where cargo exists (reported `SKIPPED_ENVIRONMENT`, never `PASS`, where it does not), and rolls back — proving the restoration — on any required-verification failure; a source matching neither known shape is refused, not guessed. Device side: probes the stock `termux-api` core tools, installs the package only when one is missing, refreshes the command hash and re-probes the same set (pkg's exit status is not the postcondition), verifies the Termux:API app independently, proves the bridge with a harmless bounded `termux-battery-status`, then probes GNSS / Wi-Fi connection / Wi-Fi scan / cell independently as `EXECUTED_VALID` / `EXECUTED_EMPTY` / `FAILED` (a failure is an unknown state, never "0 observations"); Bluetooth is an independent optional provider and never a readiness condition. Derives radar readiness from observed sensor state, detects an `hse radar` process whose process-local absent-tool cache predates the package install (`STALE_RESTART_REQUIRED`; stopped only with `--allow-process-restart`), and renders the human report and `--json` from one final-state object with stable exit codes (0 / 2 / 3 / 4 / 5 / 6 / 7 / 8 / 9). Flags: `--repo-only`, `--device-only`, `--verify-only`, `--dry-run`, `--json`, `--allow-process-restart`. Idempotent: a second clean run reports `UNCHANGED` and rewrites nothing. The core-tool list is defined once per language (`TERMUX_API_CORE_TOOLS` in the reconciler and in `install.sh`; `termux_sensor::TERMUX_API_CORE_TOOLS` in Rust) and held in lockstep by tests; the transaction itself is driven end to end by `tests/install_invariants.rs` through bash + git (dry-run/verify-only classification, patch to the shipped installer byte for byte, idempotent second run, rollback on a forced `git diff --check` failure, dirty-tree refusal, unknown-shape refusal).
- `hse import --input-format <FORMAT>` and the web upload's `?format=<name>` query parameter (with a matching selector on the Import form) force the input format instead of detecting it from content — for a file the detector cannot classify or classifies wrongly. The motivating case is real and was reproduced end-to-end: a combolist whose identities are **all** bare usernames (no email-shaped line anywhere in the file) scores 0% on the combolist heuristic, falls through to the OathNet TXT catch-all and is stored as an **empty** scan with exit 0 — silent data loss on the CLI, a "no verifiable entities" 400 on the upload — even though `parse_combolist` already handles bare usernames once reached (see the ledger for why broadening the heuristic instead is unsafe). The names are one authority: the shared `ImportFormat` enum now derives clap's `ValueEnum`, so the flag's accepted values, the upload parameter's accepted values and the label both surfaces report are the same twelve kebab-case spellings (`combolist`, `sql-dump`, `oathnet-txt`, …), locked by tests (each label against its derived name; the web selector's option list against the enum). An unknown name is an actionable error naming every accepted spelling, never a silent fall back to the detection the operator asked to bypass; forcing a format on a directory scrape is refused explicitly. The Import form's file picker also now admits `.csv` / `.kml` / `.sql` / `.log` files, which its `accept` list filtered out even though the server already parses them, and its blurb names the combolist / SQL-dump / KML formats it accepts.

- `hse import` (and the web upload) now recognises a leaked **SQL dump** — `INSERT INTO \`table\` (\`col1\`, \`col2\`, ...) VALUES (...), (...);` statements, the shape a `mysqldump`-style export of a compromised user table takes. Previously unrecognised, so it fell through to the OathNet TXT catch-all and imported as zero entities, the same class of silent data loss the combolist fix (below) addressed. The new parser (`app::import::sql_dump`) reads column semantics ONLY from the `INSERT` statement's own explicit column list — never guessed from position and never recovered from a separate `CREATE TABLE` (whose column order could disagree, silently mis-attributing a value to the wrong field; RULE.md: no fabricated findings) — unescapes both the `mysqldump` backslash dialect and the standard-SQL doubled-quote dialect unconditionally, and quarantines a row whose value count doesn't match its column list rather than guessing. Maps columns to entities using the exact same field-name conventions, confidence levels, and evidence shape as the DeHashed CSV parser, since it is structurally the same "one row = one leaked record" breach table.

- `hse import` (and the web upload) now recognises a raw **combolist** — a plain `identity:secret` (or `;`/tab-separated) credential dump with no header and no envelope, the single most common real-world breach-data shape. Previously every `looks_like_*` format check rejected it, so it fell through to the OathNet stealer-log TXT catch-all, which only recognises its own `"URL: "`/`"Username: "`-labelled lines and therefore extracted **zero** entities from a bare combolist — a real breach file silently imported as nothing. The new parser (`app::import::combolist`) sniffs the shape by content, splits each line via the same `util::extract::split_identity_secret` authority `comb_search`'s live COMB fetch already uses (promoted out of that module, zero behavioural change there), classifies the secret with the shared `classify_credential_field` gate (drops capture sentinels, recovers a mis-stored email as its own lead, never mints an identity echoed back as its own "secret"), and quarantines — counts and skips, never aborts on — a structurally malformed line (no delimiter, an empty identity, or an empty secret), reporting the count in the import summary. Routes into the existing Entity/Evidence pipeline and correlation engine exactly like every other import format.

- `hse batch` gains four more keyless-by-hand breach/stealer-log providers, each grounded in its own documentation (RULE.md: no assumed contract): HackCheck (hackcheck.io), LeakPeek, OSINTLeak (osintleak.com) and the Pentester.com free breach-check form. These are keyed/paid or account-gated APIs with a free by-hand search surface, so — like the existing DeHashed/LeakCheck/Snusbase pack entries — they are paste-ready query lists an operator runs manually, not auto-queried modules; each `accepts` only the selector kinds the provider's own docs say it indexes.
- Five keyless exposure/enrichment/geolocation modules, each an independent free corpus wired into the scan pipeline (every contract verified live against a real response, RULE.md: no assumed contract, no fabricated finding). Each fails closed on a non-2xx (a throttle/outage is a real `ModuleError`, never a false "clean"), and each ships a falsified unit-test suite pinning its found/clean/error paths. README seed-type counts and the module-overview split are updated to match the live registry.
  - `leakcheck_public` — the LeakCheck **public** breach index (`GET /api/public?check=`), keyless, returning the named breaches an email appears in plus the *categories* of data exposed (the `fields` list, e.g. `password`/`ip` — never a credential value, like HIBP's DataClasses); a second free breach corpus beside `hudsonrock`/`xposed_or_not` that can trip the `AU-001` multi-source-breach correlator with no paid key. Distinct from the keyed leakcheck.io surface in the `hse batch` provider pack.
  - `ransomware_live` — the Ransomware.live v2 victim index (`GET /v2/searchvictims/`), keyless, answering "is this domain or organisation a known ransomware/extortion victim, claimed by which group, when?" — a net-new org-exposure signal. It keeps only victims whose own `domain` matches a Domain seed or whose `victim` name matches an Organisation seed, never emitting an incidental full-text description hit as the subject. Pure discovery: it reads the public victim index and never fetches a leak site.
  - `ransomlook` — the RansomLook.io leak-site search (`GET /api/search?q=`), keyless, an independent SECOND ransomware corpus beside `ransomware_live` that also indexes markets/forums. Same precision discipline (retain only posts whose `post_title` names the seed). Wires the working `q=` param, verified by the observed response, and never the documented-but-drifted `query=` (which returns HTTP 400 and would make every scan look clean) — the drift is flagged in-code.
  - `wifidb` — HSE's **first keyless wardriving corpus**: WiFiDB (`GET /api/geojson.php?func=exp_search&mac=`), a free WiGLE alternative that resolves a BSSID to coordinates from a GeoJSON FeatureCollection, sitting beside keyed `wigle` and the keyless `mylnikov`/`beacondb` lookups. It emits a `Coordinates` fix only for a feature reporting the queried BSSID with in-range lat/lon (shared `util::geo::is_valid_coords`); GeoJSON `[lon,lat]` order handled explicitly, string `properties.lat/lon` as fallback.
  - `libravatar` — a keyless presence check for an email's public federated avatar on the open-source Gravatar alternative (`d=404` → clean 404/200 on the central CDN), reusing the single-sourced `util::gravatar::hash` MD5 identifier and sitting beside `gravatar` as an independent avatar corpus.
- The HSE BLE Radar is incorporated as the authoritative radar-domain library. `bleradar-core` (reconstructed and verified against the BLE Radar v0.3.0 APK oracle; dependency-free, `#![forbid(unsafe_code)]`) is now a pinned git dependency, and the `signal_radar` WiFi sweep uses its verified `wifi_frequency_to_channel` to derive the specific 802.11 channel (HSE previously derived only the coarse 2.4/5/6 GHz band) and its `proximity_label` to report a coarse RSSI proximity band (immediate/near/mid/far) — the RSSI axis the Bluetooth path structurally lacks on no-root Termux, on the WiFi sensor that does report signal strength. Only the crate's radar-domain surface (`signal`/`geo`/`identity`/wifi helpers) is consumed — never a fabricated distance — so the radar math has one authority; the crate's broader engines are left unused and stripped from the shipped binary by the release-profile LTO.
- Architecture ratchet `ble_radar_dependency_is_pinned_and_consumed`: the `bleradar-core` git dependency must pin a full 40-hex commit (never a floating branch/tag — a reproducible build can't compile different radar code on a rebuild) and must actually be reached by `signal_radar` (a dependency nothing calls is duplicate authority carried for nothing). Falsifiable on both halves.
- Architecture ratchet `every_wasm_ui_import_resolves_to_a_served_export`: every named import from the wasm-ui bundle (`/static/hse_wasm_ui.js`) across `src/web/js/` must resolve to a real export in the committed, `include_bytes!`-embedded bundle the browser actually receives. A renamed or removed `#[wasm_bindgen(js_name = …)]`, or a new export/import pair landed without regenerating the pkg, previously compiled and served fine yet threw `does not provide an export named …` on-device, rendering that view blank. This is the missing half of the web-UI wiring guarantee — `spa_bundle` (tests/api.rs) checks the `/static/…` *files* resolve; `wasm_ui_drift_check.sh` keeps the pkg in sync with the Rust source in CI; this locks that the JS imports resolve against the served exports. Zero current violations (all 27 imports resolve); the guard prevents future drift.
- Architecture ratchet `release_profile_stays_size_optimized`: locks the `[profile.release]` size knobs (`opt-level="s"`, `lto=true`, `codegen-units=1`, `strip=true`) plus the deliberate `panic="unwind"` (module-panic containment, never abort), so the aarch64 Termux artifact can't silently bloat — or lose its panic containment — between CI runs. The authoritative byte-size guard belongs in CI's NDK build; these are the settings it rests on.
- Architecture ratchet `the_binary_never_escalates_privilege`: the core binary must never spawn a privilege-escalation binary (`sudo`/`su`/`doas`/`pkexec`), locking HSE's no-root Termux-userland contract so it can't silently rot into an on-device failure. Zero current violations (the tool has always been no-root); the guard prevents future drift. install.sh's `sudo apt-get` is gated to the Debian/Ubuntu fallback branch — the Termux path installs via `pkg` with no sudo.
- `hse query-pack` — the manual operator query pack. For a target it generates the ranked queries to run BY HAND against the manual/paid exposure providers HSE cannot auto-query without an entitlement (IntelX, OathNet, Stolen.tax, DeHashed, XposedOrNot, HIBP), each with its query type, the provider surface to run it on, the expected result class (a multi-source gateway is flagged as non-independent; a HIBP miss is flagged as not proof of absence), and a stable `parent_query_id` grouping the pack under one seed. Purely offline and deterministic — it emits queries and destinations, makes no network call, and so declares no provider API contract. Scope is discovery / exposure verification / correlation only; it never emits account-takeover, credential-stuffing, session-replay, or authentication-bypass workflows. Every provider surface is a domain the codebase already reaches through that provider's module, so it points only at services HSE has itself verified.
- `hse dorkus` — DoRkUS, a meta search engine. It runs the clearnet multi-engine search and the dark-web (Ahmia) exposure index at once, concurrently within one time budget, and prints one aggregated, source-attributed report — where `hse query` reaches only one surface per invocation. The query is passed through verbatim, so search-operator dorks (`site:`, `intitle:`, quoted phrases) work as the underlying engines support them; `--clearnet-only` / `--dark-only` scope a run down. It is a composition over the same verified back-ends, adds no new provider or API contract, and inherits Ahmia's defensive scope — it reports where a target is mentioned and never fetches an onion service.
- Dark-web exposure now runs during a scan. Ahmia's clearnet-served index of Tor hidden services — the search behind `hse query --dark` — was reachable only from that one command, so an ordinary `hse scan` never checked the dark web at all. The verified search is now wired into the scan pipeline as the keyless `ahmia` module: for an email, username, name, domain, or organisation it surfaces each onion page that mentions the target as an exposure finding. Every hit is a full-text mention, so it is graded conservatively and flagged for identity verification, the same discipline the court and newspaper-archive sources use. The module reports where a target is exposed and never fetches an onion service — a marketplace-directory capability stays deliberately out of scope. Telegram username presence was already covered by `username_search`.
- The scan engine will never fetch a Tor `.onion` service. `core::validation::is_onion_url` plus an expansion-loop gate mean a discovered onion URL is recorded as an exposure finding but never dispatched to the crawler, so no module — present or future — can turn a dark-web mention into an attempted onion fetch. The skip is recorded as `onion_not_fetched`.
- A Vietnamese domain now carries the jurisdiction signal an Australian one always had. The geo-domain classifier tabulated only `.com.vn`, so a `.gov.vn` government body, a `.edu.vn`/`.ac.vn` institution, a `.org.vn` non-profit, a `.name.vn` individual and every directly-registered `.vn` fell through to no country classification at all — the same "real second-level domain, no jurisdiction signal" gap the `.id.au`/`.asn.au` rows had already closed for Australia. The full VNNIC second-level namespace (Circular 24/2015/TT-BTTTT, mirrored in the Public Suffix List) is now classified to Vietnam, and each second-level domain's registrant type — government, education, commercial, non-profit or individual — is tagged on the emitted Address (`vn-registrant:*`) exactly as the `.au` registrant is, read off the published domain hierarchy with no network call. Vietnam is HSE's host operating jurisdiction; this makes a `.vn` domain a first-class geolocation signal rather than an unclassified string.
- `hse batch` turns one seed, or a whole stored scan, into a paste-ready list of bulk queries for high-yield breach and stealer-log sites — for when an API key is not an option and the operator must run the search by hand. It fans a seed out into the selectors a breach site indexes (email, username, phone, domain, IP, name) with the same generator `oathnet-batch` uses, de-duplicated across surfaces, and prints them one query per line in each provider's own documented syntax: nine services grounded in their own docs (OathNet, SeekNow, Stolen/stolen.tax, DeHashed, LeakCheck, Snusbase, Intelligence X, Leak-Lookup, Have I Been Pwned), DeHashed as `field:value` (names with spaces quoted) and the rest bare. `--site` narrows the set, `--bare` drops the comment headers for a clean paste, `--format json` gives the structured plan, and `--out` writes a file. Over HTTP the same list is an operator-only download (`GET /api/v1/scans/{id}/batch.txt`) that names providers by design and never goes through the client-facing redactor.
- `hse sf` is SpiderFoot 4.0's `sf.py` command line, on HSE's engine — so an operator's habits and scripts carry over (`hse sf -s <target> -u passive -o csv`). The flags, their help, the validation order and error strings, the target-type detection (including sf.py's pre-quoting of the seed), the tab/csv/json row layouts and the `-M`/`-T`/`-C` listings were all read from SpiderFoot's own source at tag v4.0. A use case maps onto HSE's scan options (`passive` → passive-only modules, `footprint` → every module bar threat-intel, `investigate`/`all` → all), `-m` selects HSE modules, `-t`/`-F` filter printed rows by SpiderFoot type, and HSE entity kinds print under their SpiderFoot type name where one exists. One deliberate, documented deviation: SpiderFoot's csv writer emits four columns under a three-column header unless `-r` is given; here the row and header always agree.
- The command line now has one spelling per concept, enforced by a test. Output format is `--format` (`-f` where it's free), an output file is `--out` (`-o`), a stored scan is `--scan-id` (`latest` allowed) — and the older `--output` / `--output-format` / `-o` / `-F` spellings keep working as hidden aliases, so existing scripts don't break while no help page advertises a retired name. Provider and noun spellings are fixed to one form too (OathNet, SeekNow, DeHashed, API key, scan ID), documented in `docs/GLOSSARY.md`; a lock reads every `hse … --help` page against that glossary and fails on any drift.
- Provider coverage is recorded, and silence is no longer mistaken for a negative. `core::intelligence` gains `ProviderOutcome` — observed, clean-negative, not-attempted, or failed, each unresolved case naming its reason — and the ledger refuses to reject a claim while any provider bearing on it never actually answered. A source that broke, ran out of quota, or was never configured can no longer be counted as having said no. Coverage is checkpointed with the ledger, so a resumed scan still knows what it is owed, and older checkpoints still load.
- A location can no longer claim precision its basis never had. Every `LocationBasis` carries an honest floor (a directly observed fix down to 10 m; an IP-derived one no tighter than 25 km), and an assertion below its floor is now invalid instead of being stored as though it were a doorway. Bases that locate the *subject* are marked apart from those that locate something merely associated with them — an egress, a registered office, an administrative area. Two locations are never averaged: they narrow to the tighter constraint when they overlap, and are preserved as an explicit, cross-linked conflict when they do not.
- The headline location estimate no longer claims precision none of its sources had. A fix fused from several sightings reported the spread between them as its radius, so two city-grain signals that happened to agree closely — a search-snippet geocode and a social-profile bio both naming the same city — produced a ± 0.2 km answer from sources good to 5 km at best. The fused radius is now floored at the finest contributing observation: agreement corroborates the area, it does not synthesise a street.
- The headline location now says whether it observed the subject or a place associated with them. A registered office, a breached postcode, an ISP allocation block and an area-code region are all real places that can be right about the address and wrong about the person; only a handset fix, a photo's GPS, or the Wi-Fi access points the subject's device can see are sightings of the subject. `report.json` carries the verdict as `best_location.locates_subject_directly` and the dossier prints an explicit note under any fix that did not.
- A scan now reports what it managed to ASK, not only what it found. `report.json`, the CLI dossier and the web console's Summary tab each carry the same provider-coverage block, derived from the scan's own dispatch events: which providers answered, which broke, which were never queried, and why. Without it a thin result was ambiguous — a sweep that queried everything and found little and one where a third of its providers failed rendered identically, and only the first is evidence of absence. Coverage that is simply unknown (an old scan whose event log has been pruned) is reported as unknown, never as a clean bill of health.
- New endpoint `GET /api/v1/scans/{id}/coverage`, feeding the console's Provider Coverage panel.
- The Ollama removal is now complete: the LoRA training tooling under `scripts/finetune/`, a dormant daemon poll method on the storage port and three stale comments were still in the tree, and the removal lock now scans the whole live tree, by path and by content, so a leftover or a quiet re-add fails CI. `hse export/diff/audit latest` resolves the latest scan through the indexed status column instead of a JSON full scan.
- The Ollama / local-AI integration is gone: the `hse analyze` command, the `hse-ai-daemon` binary, the `hse-ai` wrapper, the `feature.ai_daemon` toggle and the installer's model bootstrap. It was opt-in, off by default and never touched by a scan — and its disk probe was what killed the installer on a real device. Existing databases are unaffected.
- `hse report` replaces three separate commands with one that answers the whole question. `audit`, `benchmark` and `gaps` are three lenses on the same completed scan; `hse report --scan-id latest` now runs all three. The individual commands still work for scripts. The visible command list is down from 21 to 19.
- A first install on a clean Termux no longer throws away the prebuilt binary and compiles from source. Revision resolution used `git`, but ran before the step that installs git — so on a fresh device it always failed, the downloaded and sha256-verified binary was always rejected as unverifiable, and every new user paid for a full on-device Rust build. It now resolves the revision over curl when git is absent.
- The installer no longer says a downloaded binary is "built from a different commit" when it could not determine the commit at all; it now distinguishes a mismatch from an unverifiable one and names the flags that override it.
- A successful install no longer reports failure. One `df -Pm` in the optional local-AI step — a flag Termux's `df` does not support, as the installer's own preflight comment already noted — killed the whole script under `set -e`, so an install where every step succeeded ended in "Installation failed (exit 1)" and `hse update` in an error. The optional step can no longer fail the install at all.
- `hse doctor` no longer counts unfilled template slots as configured keys. On a fresh install it reported "62 keys loaded" with zero real values, and — worse — hid the entire list of keys worth acquiring, because a name being present counted as it being set. It now reports what is actually usable and shows the 54 keys still to register.
- `hse doctor` no longer reports "no modules currently show a failure streak" directly above a list of sources that are failing. That line reads a per-process tracker which is always empty in a `doctor` run, because doctor never dispatches anything — so it was a constant, not a measurement. It now says it wasn't measured and points at the section with the recorded outcomes, while still reporting a real all-clear when a process actually ran modules.
- HSE no longer tells you to renew API keys you never set. Unfilled template slots were being handed to providers as credentials, and the resulting 401s were reported back as "configured key rejected — replace or renew". Placeholders are now barred at the point any pooled key is handed out, whichever way it got into the pool.
- Unfilled key slots are no longer added to the rotation pool, so `hse keys validate` no longer spends live requests probing placeholder text and reporting providers as rejecting credentials you never supplied.
- SeekNow's within-scan response cache is now actually within-scan. Keyed globally, a concurrent scan could be served records another scan had fetched — provider output attributed to a scan that never made the call — and starting a scan wiped a running one's cache.
- Typosquat findings are no longer lost between concurrent scans. The module's within-scan dedup was a single shared set, so once one scan had covered a domain a second scan running at the same time silently produced nothing for it. The set is now per scan.
- Two SeekNow latches that were documented as per-scan were in fact process-wide, so concurrent scans in a long-lived `hse serve` interfered: the first scan to probe the quota left every sibling pinned to the un-scaled default cap, and one scan hitting a rejected key made every sibling report a failure it never saw. Both now live in the same per-scan state the other quota flags use.
- The same double-counting is fixed for Wi-Fi and network registry data, and a build check now catches the next instance. `wifi_intel` resolves access points through WiGLE and `ip_registry` reads the same BGPView endpoints as the standalone modules for those providers; findings from each are now attributed to the database they came from. The check found the BGPView case on its first run.
- A cell tower's position is no longer counted twice. `cell_intel` geolocates towers by querying OpenCelliD, and the standalone `opencellid` module queries the same database with the same key for the same towers — so the identical position arrived under two source names, merged, and read as two independent sources agreeing. It is now attributed to the database it came from, so retrieving one record twice no longer raises confidence. The tower's radio detection, which really is an independent observation, is unaffected.
- The benchmark report now says whether its own scorecard is safe to compare against another run's. A run whose providers had no credential yields fewer entities for a reason that has nothing to do with the configuration being tested, and the two scorecards looked identical; `hse benchmark`, the API and the console now carry the caveat, above the numbers rather than below them.
- Provider coverage separates what BROKE from what the scan simply did not ask. Narrowing a sweep is ordinary — an allowlist, a category focus, free-only — so a single "incomplete" count would look alarming on every scan and be ignored on all of them. The report, the API, the dossier and the console now say "every available provider answered; N were out of scope" when nothing is wrong, and reserve the warning for providers that could not be used.
- Skipped modules now record WHY they were skipped as a structured class rather than only as prose, so a provider that was deduped because it already ran, or one that could never have answered about a private address, is no longer reported as a coverage gap. Only two of the four kinds of skip — the operator narrowing the sweep, and a provider that could not be used — leave a provider owing an answer.
- Consolidated onto one intelligence model. The `core::claim` and `core::geo_confidence` layers added earlier in this cycle duplicated `core::intelligence`, which landed separately with a stronger source-lineage model, and have been removed; only the parts above, which `core::intelligence` genuinely lacked, were carried across.
- GEOINT frontier preference: the dispatch-utility model gains a bounded `W_GEO` term (0.25, against `W_INFO` 3.0) derived from each module's own declared outputs and category, so geolocatable work is attempted ahead of otherwise-equal alternatives without ever outranking stronger evidence. Visible in the dispatch explanation and wired at the live call site.


- T3 quality: AU-002 identity-cluster implausibility rejection signaling as AU-002-REJECT finding
- `Module::is_derivation()`: a module declares that its output is a deterministic transform of data already in the graph (parser, canonicaliser, permutation generator, offline decoder). An architecture test pins the declaration to `hse_core::ENRICHMENT_ONLY_SOURCES` in both directions, so the "does this source corroborate?" fact has one enforced authority instead of a hand-maintained list.
- `util::paths::isolate_for_tests()` + `tests/common::isolate_home()`: integration-test crates (where `cfg!(test)` is false in the linked library) now redirect the whole `~/.huntsman` layout at a per-process temp dir; an architecture test pins that no production code can call it.

### Changed

- `ip_registry` reads ASN registrations from RDAP `autnum` (`https://rdap.arin.net/registry/autnum/{asn}`, ARIN's root redirecting to the authoritative RIR) instead of the retired BGPView API, and drops its duplicate BGPView IP → ASN half (`ripestat` is the authority). Review of the first cut tightened the contract further: only a reply that *says* the registry holds nothing (`No match for …`, `NOT FOUND`, DENIC `Status: free`, RIPE `ERROR:101`, `No entries found`, …) is the clean negative — an empty reply, a banner or an unknown dialect is a lookup failure; a referral-less IANA answer is classified before it is called "no WHOIS server" (a refusal is `RateLimited`, `0 objects` is a typed skip, anything else a failure); a URL host given as a bracketed IPv6 literal is queried and classified as the address; skip and refusal messages name the looked-up host, never the URL's path, query or userinfo; behind an HTTPS proxy a URL with an address host takes the RDAP path like a bare address; and the CDN/anycast geolocation suppression runs on the looked-up address rather than the raw target, so `http://104.16.0.1/…` no longer geolocates the subject to Cloudflare's registered country.

## Rationale

Per Rule 0.7 (Decision Hierarchy), all changes prioritize:

1. **Correctness** — code must work (all tests pass, gate passing)
2. **Evidence Integrity** — data must be valid (no silent failures, explicit error attribution, honest consensus validation)
3. **Safety** — no undefined behavior (`#![forbid(unsafe_code)]`)
4. **Determinism** — reproducible results (no flaky tests, no ordering leaks)
5. **Reproducibility** — repeatable across runs (deterministic sorts, tie-breaks, no HashMap iteration leaks)

Later priorities (6-10: simplicity, performance, maintainability, portability, convenience) are deferred until P0-P2 defects are closed.
